### **The Dual-Format Crisis**

Dispatch 004 established the core limitation of autoregressive foundation models. They collapse structural blueprints into a single sequence of probabilistic tokens. Statistical guessing may work for open-ended text generation, but in regulated enterprise governance, it creates systematic errors.

Enterprise data exists simultaneously in two divergent formats because document creation typically begins in an editable Microsoft Word (.docx) file, whereas the finalized, published version is rendered into an immutable PDF for distribution and archiving. The OpenXML source tree in the authoring document serves as the single source of truth. It holds explicit semantic hierarchies, document object model (DOM) nodes, table matrices, and schema definitions, but lacks fixed physical rendering coordinates. Conversely, the rendered PDF serves as the visual artifact. It contains two-dimensional layout vectors, text operators, and bounding boxes, but carries no native semantic hierarchy.

Modern software treats these formats as isolated structures. Parsers extract raw text out of a PDF and discard visual geometry, or they flatten an OpenXML tree (.docx) into plain text and destroy XML DOM lineage. High-integrity document control requires a unified model. Topological co-registration constructs a structure-preserving isomorphism between the logical source tree and its rendered visual artifact.

### **Medical Physics and Surface Topology**

To link an OpenXML DOM tree to a rendered PDF without string matching, we adapt a framework from medical imaging. Fusion imaging pairs two independent sensor modalities to establish a single ground truth. A PET scan, for example, maps metabolic activity, recording tissue function without sharp anatomical borders. An OpenXML document behaves similarly by providing functional semantics including DOM depth, style tags, and table cell relationships while lacking physical coordinates. In contrast, a CT scan provides spatial geometry, recording physical structures on a coordinate grid without metabolic context. A PDF operates like a CT scan by providing exact visual coordinates including bounding boxes and font baselines without semantic context.

Co-registration maps functional semantic nodes directly onto visual layout coordinates through three transformations. Rather than flattening structural hierarchy, TRACE vectorizes the discrete OpenXML DOM Directed Acyclic Graph (DAG) into an edge-preserving vector point cloud, encoding parent-child lineage, tree depth, and schema invariants directly into coordinate dimensions. The Pelizzari surface matching algorithm then evaluates this topologically ordered point cloud using PDF bounding-box polygons as the target surface manifold. Minimizing the surface displacement error E\_surface guarantees spatial convergence without character matching or loss of AST lineage.

Stereotactic baseline realignment uses structural landmarks such as page margins, headers, and title blocks to define the reference axis u\_ref. Aligning this baseline cancels rendering variations from dots per inch (DPI) scaling and font metrics before evaluating individual paragraph vectors. Finally, cross-modal mutual information replaces rigid string matching with a structural functional:

I(X\_DOCX; X\_PDF) = H(X\_DOCX) + H(X\_PDF) - H(X\_DOCX, X\_PDF)

This functional measures shared information entropy rather than character equality. As a result, nodes co-register across text reflows, font scaling, hyphenation, and column wraps.

### **3-6-1 Phase Space and Cache Alignment**

The co-registration engine evaluates both document states within a 3D continuous control vector:

x(t) = [X(t), Y(t), Z(t)]

The X(t) axis encodes relative tree depth, Dewey coordinate paths, and table cell matrix coordinates for OpenXML, mapping directly against PDF bounding box layout vectors.

The Y(t) axis tracks section categories, parent heading proximity, and container boundaries, acting as the attractor pulling state trajectories toward their target context.

The Z(t) axis measures alignment displacement E\_align and schema health.

To eliminate pointer chasing and cache line thrashing, TRACE decouples state tracking from storage. The control plane vector consists of three contiguous 64-bit double-precision floats totaling 24 bytes. Arranged in aligned memory structures, single instruction multiple data (SIMD) vector units evaluate up to 16 state trajectories simultaneously in a single instruction cycle. Meanwhile, the payload vector runs in a contiguous memory buffer, carrying raw text strings, normalized UTF-8 bytes, extracted dates, author provenance, and vector masks alongside the control vector.

### **The TRACE Protocol Architecture**

The formal framework governing this architecture is the TRACE protocol, which stands for Template Referenced Analysis and Content Examination. Adapting the dynamic time-constant formulations of Liquid Neural Networks, TRACE replaces unconstrained statistical activations with schema-driven differential equations. To guarantee that system velocity drops to zero during structural faults, the dynamic viscosity factor 1 / tau(x, t) acts as a global scalar multiplier across the state derivative:

dx/dt = (1 / tau(x, t)) \* [-x(t) + S(x, u, t) \* (A - x(t))]

Here A represents the target structural attractor, while S(x, u, t) is the input drive function, and tau(x, t) is the dynamic state viscosity. Dynamic viscosity tau(x, t) couples directly to the alignment energy functional E\_align(x\_DOCX, x\_PDF):

tau(x, t) = tau\_0 + gamma \* E\_align(x\_DOCX, x\_PDF)

When state parity holds (E\_align approaches 0), dynamic viscosity approaches its baseline (tau ≈ tau\_0). This permits state velocity dx/dt to operate at full speed to snap the logical DOM node onto its physical PDF coordinate. In the presence of alignment errors (E\_align approaches infinity), dynamic viscosity grows rapidly (tau(x, t) approaches infinity). Factoring 1 / tau out globally yields the limit where dx/dt equals 0 as E\_align approaches infinity.

Because 1 / tau scales the entire derivative, state velocity drops to zero. The invalid payload freezes at the origin (0, 0, 0) in dynamic superposition, holding the node in a zero-copy quarantine ring buffer without guessing or crashing. ### **Enterprise Applications of Co-Registration**

Topological co-registration addresses four specific document processing requirements where standard parsers fail.

* **Visual Drift Detection:** Addresses cases where PDF files diverge from the source tree, whether through manual post-export edits or faulty conversion engines. PDF converters frequently introduce font substitution shifts, margin offsets, or line-wrap anomalies during export that alter visual geometry without changing the text. Surface matching measures physical displacement between target PDF bounding boxes and OpenXML source nodes. Consequently, both rendering engine faults and unauthorized post-export edits increase E\_align, driving tau to infinity and flagging the exact displaced coordinate immediately.
* **Stream-Level Redaction:** Resolves the problem of visual redactions that obscure visible text while leaving underlying PostScript text streams intact inside the file. Redacting a paragraph in the source tree projects the two-dimensional vector bounding box onto the PDF, removing target PostScript bytes at the stream level.
* **Bi-Directional Audit Traversal**: Eliminates the manual overhead of cross-referencing published PDF packages against source repository files. A spatial TRACE link allows an auditor clicking any element in a PDF to jump directly to the corresponding XML line and commit hash in the source repository.
* **Structured Data Ingestion**: Fixes the problem of broken table layouts and scrambled reading orders during PDF extraction. The co-registration engine uses the source tree to assign semantic labels directly to PDF layout blocks.
