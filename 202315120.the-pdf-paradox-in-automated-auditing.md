For decades, the portable document format (PDF) has been the standard for ensuring data integrity against human interference. By finalizing documents into a visually fixed, immutable format, organizations have successfully prevented unauthorized human tampering, creating a “gold standard” for record retention and archival.

> However, in our effort to automate the verification of these records, we are encountering a new architectural issue. The same properties that make a PDF a reliable shield against human corruption also make it a significant hurdle for machine-based verification.

We are now navigating this paradigm: we are using tools designed for human stability to feed AI systems designed for data extraction. This requires us to be exceptionally cautious about how we approach this pipeline.

### **The Integrity Trade-off**

When auditing systems ingest a native `.docx` file, they are processing a tree-structured data file (serialized hierarchical package). Internally, the document is organized as a structured XML tree (`document.xml`). The structural labels (tags) provide deterministic boundaries that define the beginning and end of every data element. This structure allows an automated system to “contain” the information, directing the AI’s attention precisely to the content while ignoring metadata or visual formatting.

However, common industry practice frequently equates the *security* of a locked PDF file with the *extraction fidelity* of the Single Source of Truth (SSOT).

The process of flattening a native file into a PDF file strips this underlying data structure. The AI is forced to rely on proximity (the distance between serialized tokens) to infer context. Without explicit boundaries, the AI’s ability to focus its attention on the right information becomes unbounded (unbounded attention mechanisms). This creates a tendency to blend data, and elevate hidden metadata.

### Empirical Indicators: The Integrity of Archival Pipelines

To quantify the operational risk of architectural divergence, we conducted a simple experiment assessing how standard enterprise archival pipelines process documents containing complex regulatory structures.

We selected **21 CFR Part 11** as our model corpus because it serves as the definitive legal framework for data integrity. The goal was to determine if standard conversion and extraction pipelines preserve the structural boundaries necessary to meet the regulation’s own requirements.

Our experiment did not analyze the FDA’s original source text for errors. We analyzed the *behavior of the archival pipeline* when processing complex document structures common in regulated environments (such as tabular data, multi-level headers, and document control footers).

Testing standard enterprise PDF archival pipelines against this model corpus indicates that the transformation process introduces systematic extraction drift:

* **Tabular Distortion:** Complex regulatory controls, such as those defining system thresholds, often require tabular formatting. During the conversion to PDF, the extraction pipeline flattened certain tables into unordered text strings.
* **Header/Footer Fusion:** To ensure traceability, regulated documents typically require administrative metadata (Document IDs, versioning, page markers) in the headers and footers. During PDF ingestion, the extraction engine frequently failed to distinguish between these administrative strings and the regulatory text, interleaving metadata into the core compliance clauses.

### **The Path Forward**

The data indicates a need for a deterministic component where structural boundaries (such as XML tags) are verified before content is processed. We need to ensure that the archival process does not undermine the very data integrity it was designed to protect.
